# 评测语料（公开知识、自造表述，不含任何真实用户材料）

以下 20 个段落是检索评测的语料。每个二级标题自带段落编号（P01~P20），
评测集的 expected 引用的就是这些编号。内容为通用技术常识的自造复述，
不保证是最权威表述——它们是检索的「靶子」，不是教材。

## P01 JVM 垃圾回收判定

Java 虚拟机通过可达性分析判断对象是否存活：从 GC Roots（栈帧局部变量、静态字段、
JNI 引用等）出发，不可达的对象即可回收。引用计数法因循环引用问题未被 HotSpot 主线采用。

## P02 Spring Bean 默认作用域

Spring 容器中 Bean 的默认作用域是 singleton，整个容器一个实例。prototype 每次获取
都创建新实例；request、session 作用域只在 Web 容器中可用。

## P03 Spring 事务传播行为

事务传播行为 REQUIRED 是默认值：当前存在事务就加入，不存在就新建。REQUIRES_NEW
总会开新事务并挂起当前事务，嵌套事务回滚不会连带外层。

## P04 InnoDB 默认隔离级别

MySQL InnoDB 在未显式配置时默认使用 REPEATABLE READ（可重复读），并通过间隙锁在
一定程度上防止幻读。标准 SQL 的四个隔离级别由弱到强为：读未提交、读已提交、可重复读、串行化。

## P05 常见索引失效场景

对索引列做函数运算、隐式类型转换、前导模糊匹配（LIKE '%xx'）、以及 OR 连接非索引列，
都会让优化器放弃走索引。排查慢 SQL 时先看执行计划里的 type 与 rows。

## P06 HTTP 401 与 403

401 表示未认证：请求者身份未知，应当引导登录或刷新凭证。403 表示已认证但无权限：
服务器知道你是谁，但拒绝执行。混淆两者会让客户端无法判断该重新登录还是该申请授权。

## P07 Redis 过期键删除策略

Redis 对过期键采用惰性删除与定期删除的组合：访问时发现过期才删（惰性），后台周期性
抽样清理（定期），以此在 CPU 与内存之间折中，不依赖单独的过期线程扫全库。

## P08 JWT 令牌结构

JWT 由 Header、Payload、Signature 三段组成，以点号连接，各段是 Base64Url 编码。
签名保证前两段不可篡改；Payload 只是编码而非加密，不应放敏感明文。

## P09 HashMap 与 Hashtable 线程安全

HashMap 非线程安全，并发写入可能丢数据；Hashtable 的方法级 synchronized 保证安全但
吞吐差。现代实践用 ConcurrentHashMap：分段/CAS 细粒度并发，兼顾安全与性能。

## P10 ArrayList 与 LinkedList 随机访问

ArrayList 底层是数组，随机访问 O(1)；LinkedList 是双向链表，随机访问要从头或尾遍历，
为 O(n)，但头尾插入删除是 O(1)。按位置读多写少选 ArrayList。

## P11 接口与抽象类

接口的方法默认公开抽象，一个类可以实现多个接口；抽象类只能单继承，但可以持有状态
和构造逻辑。Java 8 后接口允许 default 方法，缩小了与抽象类的差距。

## P12 Spring Boot 自动配置

Spring Boot 通过 @EnableAutoConfiguration 加载各 starter 的自动配置类，配合
@ConditionalOnClass、@ConditionalOnMissingBean 等条件注解按需生效。应用自定义的
同类型 Bean 会覆盖自动配置。

## P13 TCP 三次握手

三次握手的核心目的是同步双方的初始序列号并确认双向可达。两次握手无法防止历史失效
连接请求造成的资源浪费，四次则冗余。

## P14 进程与线程

进程是资源分配的基本单位，拥有独立地址空间；线程是调度执行的基本单位，同一进程内
的线程共享堆与方法区，各自持有栈与程序计数器。线程切换成本远低于进程切换。

## P15 B+ 树与 B 树

B+ 树的非叶子节点只存键，数据全在叶子节点且叶子间有链表相连，范围扫描沿链表顺序读，
比 B 树反复回溯中序遍历高效。数据库索引普遍选择 B+ 树。

## P16 消息队列的三大作用

消息队列的典型价值是削峰（把瞬时写压力摊平到消费端）、解耦（生产者不依赖消费者存活）
与异步（主流程不等慢操作）。代价是多一套需要运维的基础设施与最终一致性。

## P17 SQL 注入的防御

参数化查询（PreparedStatement 占位符）是 SQL 注入的根本防御：用户输入永远作为数据
而非 SQL 片段被解析。拼接 SQL 字符串、把用户输入直接放进动态表名列名都是高危做法。

## P18 REST 方法的幂等性

PUT 与 DELETE 是幂等的：重复执行效果一致；POST 不幂等，重复提交会创建多份资源。
网络重试场景下，把创建操作设计成客户端生成幂等键是常见补救。

## P19 单元测试与集成测试

单元测试不依赖外部基础设施，毫秒级运行，验证一段逻辑的分支；集成测试真实连接数据库
等依赖，验证组装后的链路。两者比例失衡（全集成）会让反馈周期长到没人愿意跑测试。

## P20 乐观锁与悲观锁

乐观锁假定冲突少，提交时用版本号比对失败即重试；悲观锁假定冲突多，先锁再改。
读写比高时乐观锁吞吐更好，热点行竞争激烈时悲观锁减少无效重试。
